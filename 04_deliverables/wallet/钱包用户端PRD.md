## 1. 产品背景与目标

### 1.1 背景

商城已具备完整的钱包后台管理体系（充值方案、提现审核、交易流水、商户签约等），但用户端缺少对应的钱包入口与页面。用户无法在商城中查看余额、充值、提现、查询交易明细。

### 1.2 目标

- 提供用户端「我的钱包」入口，用户可从商城「我的」页面进入
- 用户可查看余额构成（本金/赠送/冻结）、完成充值、发起提现、查询交易明细
- 与后台配置联动：充值档位、充值活动、提现规则均来自后台配置
- 明确演示元素与真实产品的边界（冻结演示按钮仅原型用，实际不存在）

### 1.3 成功指标

- 用户可在 3 步内完成一次充值
- 用户可在 3 步内发起一次提现
- 余额、充值、提现、明细数据与后台管理端一致
- 页面上的业务规则说明与后台配置口径一致，无歧义

## 2. 产品范围

### 2.1 包含功能

| 模块 | 功能点 |
|------|--------|
| 入口 | 商城「我的」页面 → 我的钱包入口（含余额摘要） |
| 钱包首页 | 余额总览、状态展示、快捷操作、最近交易预览 |
| 充值 | 预选档位、自定义金额、活动提示、模拟支付、充值记录 |
| 提现 | 可提现金额、金额输入、手续费计算、提现记录 |
| 交易明细 | 全类型流水、筛选、详情（含资金去向） |
| 基础状态 | 冻结提示、提现中金额展示 |

### 2.2 不包含功能

- 钱包支付（下单时使用钱包余额抵扣）
- 实名认证、支付密码
- 客服代操作、后台管理功能
- 用户端自行开通/关闭钱包
- 用户端展示收款商户信息（后台签约的收款方为内部信息，用户端不展示）

## 4. 功能需求

### 4.1 入口

**需求描述**：商城「我的」页面提供「我的钱包」入口，展示余额摘要，点击进入钱包首页。

**页面内容**：

| 元素 | 说明 |
|------|------|
| 入口标题 | 「我的钱包」 |
| 余额摘要 | 显示总余额（如 ¥1,280.50），余额为 0 显示 ¥0.00 |
| 右侧箭头 | 指示可点击进入 |

**交互说明**：
- 点击入口 → 跳转钱包首页

**验收标准**：
- [ ] 「我的」页面展示钱包入口及余额摘要
- [ ] 点击入口进入钱包首页

---

### 4.2 钱包首页

**需求描述**：用户进入钱包后的主页面，展示余额总览、钱包状态、快捷操作与最近交易。

**4.2.1 余额总览卡片**

| 字段 | 说明 |
|------|------|
| 总余额 | 本金 + 赠送，大号数字展示 |
| 本金（可提现） | 本金桶余额，主色标识 |
| 赠送 | 赠送桶余额，橙色标识，标注「不可提现」 |
| 冻结金额 | 系统冻结金额，灰色标识 |
| 提现中 | 提现冻结金额，灰色标识 |

**口径说明**：
```
总余额   = 本金 + 赠送
可用余额 = 总余额 − 冻结金额 − 提现中
```

**4.2.2 钱包状态**

| 状态 | 展示 |
|------|------|
| 正常 | 无特殊提示 |
| 已冻结 | 红色提示条：「钱包已被冻结，原因：xxx」，充值/提现按钮置灰不可点击 |

**4.2.3 快捷操作**

| 按钮 | 动作 |
|------|------|
| 去充值 | 跳转充值页 |
| 去提现 | 跳转提现页（钱包冻结时置灰） |

**4.2.4 最近交易预览**

- 展示最近 5 条流水：类型标签（充值/消费/退款/提现/冻结）、金额（正负颜色）、时间
- 底部「查看全部」→ 跳转交易明细页

**验收标准**：
- [ ] 余额总览金额拆分正确（总余额 = 本金 + 赠送）
- [ ] 冻结钱包时提示原因且充值/提现不可用
- [ ] 最近交易展示 5 条且数据正确

---

### 4.3 充值

**需求描述**：用户选择金额完成充值，收款商户为后台签约的收款方，充值档位与活动来自后台「充值方案」配置。用户端不展示收款商户信息。

**4.3.1 充值金额选择**

| 元素 | 说明 |
|------|------|
| 预选档位 | 后台配置的预选金额（如 ¥50/¥100/¥200/¥500/¥1000），点击选中 |
| 自定义金额 | 后台允许自定义时显示输入框，限制最低/最高 |
| 活动提示 | 命中后台活动时展示：如「满100送10」「充500打95折」 |

**交互说明**：
- 点击预选档位 → 选中态高亮（蓝框浅蓝底 + ✓），自定义输入框清空
- 输入自定义金额 → 预选档位取消选中
- 金额不合法（超限）→ 输入框红框提示

**4.3.2 确认支付（模拟）**

| 元素 | 说明 |
|------|------|
| 支付金额 | 用户实际支付金额 |
| 到账金额 | 支付金额 + 活动赠送（如命中赠送活动） |
| 确认充值按钮 | 点击弹出确认 |

**交互流程**：
```
选择金额 → 点击确认充值 → 确认弹窗（支付金额/活动赠送/预计到账）
  → 确认 → 模拟支付 loading → 支付成功 → 余额刷新（本金+支付额、赠送+赠送额）→ 返回首页
```

**4.3.3 充值记录**

| 字段 | 说明 |
|------|------|
| 充值单号 | 如 RCH-20260805-001 |
| 支付金额 | 用户支付金额 |
| 到账金额 | 实际入账金额 |
| 赠送金额 | 活动赠送（无则 -） |
| 状态 | 待支付 / 已到账 / 入账失败 |
| 时间 | 申请时间 |

**验收标准**：
- [ ] 预选档位与后台充值方案一致
- [ ] 自定义金额限制最低/最高生效
- [ ] 命中活动时到账金额 = 支付金额 + 赠送
- [ ] 充值成功后余额增加且记录出现在充值记录
- [ ] 页面任何位置不出现收款商户信息

---

### 4.4 提现

**需求描述**：用户将可提现余额（本金桶）提现，规则来自后台「钱包设置」。

**4.4.1 提现表单**

| 字段 | 说明 |
|------|------|
| 可提现金额 | 本金桶余额展示 |
| 提现金额输入 | 用户输入，右侧「全部提现」快捷填入 |
| 手续费 | 后台配置：固定金额或比例（如 0.5%），自动计算 |
| 实际到账 | 提现金额 − 手续费 |

**校验规则**（后台配置驱动）：

| 规则 | 说明 |
|------|------|
| 最低提现额 | 低于 minWithdraw 提示 |
| 最高提现额 | 高于 maxWithdraw 提示 |
| 余额内 | 超过可提现余额提示 |
| 每日限额 | 当日累计提现超 dailyWithdrawLimit 提示 |

**4.4.2 提现记录**

| 字段 | 说明 |
|------|------|
| 提现单号 | 如 WDR-20260805-001 |
| 提现金额 | 申请金额 |
| 手续费 | 扣取金额（无则免） |
| 实际到账 | 到账金额 |
| 状态 | 待审核 / 处理中 / 已到账 / 已拒绝 |
| 拒绝原因 | 已拒绝时展示 |

**验收标准**：
- [ ] 手续费按后台配置（固定/比例）正确计算
- [ ] 四项校验规则均生效并有明确提示
- [ ] 提现成功后提现中金额增加、可提现金额减少
- [ ] 提现记录状态与后台提现管理一致

---

### 4.5 交易明细

**需求描述**：展示用户全部资金流水，支持筛选与详情查看。

**4.5.1 流水列表**

| 字段 | 说明 |
|------|------|
| 类型 | 充值 / 消费 / 退款 / 提现 / 冻结 |
| 金额 | 收入正数（红）、支出负数（绿） |
| 时间 | 交易时间 |
| 关联单号 | 充值/提现/订单单号 |

**筛选**：按类型筛选（全部/充值/消费/退款/提现/冻结），点击类型切换列表。

**4.5.2 流水详情**

- 点击流水行 → 底部弹窗详情
- 内容：类型、金额、时间、关联单号、备注
- **资金来源（先进先出）**：消费/退款流水展开资金来源明细（关联充值批次、扣减金额、批次剩余）

**验收标准**：
- [ ] 全部流水类型正确展示
- [ ] 类型筛选生效
- [ ] 消费流水详情展示 FIFO 资金来源批次

---

### 4.6 基础状态

**需求描述**：钱包异常状态的处理与展示。

| 场景 | 行为 |
|------|------|
| 钱包冻结 | 首页展示冻结原因；充值/提现按钮置灰；禁止充值/提现操作 |
| 提现中金额 | 首页「提现中」展示，提现时可用余额自动扣除已提现中金额，防止重复提现 |
| 无数据 | 流水/记录为空时展示空态提示 |

## 5. 全局业务规则

### 5.1 余额口径

```
总余额   = 本金 + 赠送
可用余额 = 总余额 − 冻结金额 − 提现中
本金     = 可提现（提现只可提本金桶）
赠送     = 不可提现（活动赠送入赠送桶）
```

### 5.2 充值活动命中规则

| 活动类型 | 规则 | 示例 |
|---------|------|------|
| 满赠 | 单笔充值金额 ≥ 门槛，赠送固定金额 | 满100送10 → 充100到账110 |
| 折扣 | 单笔充值金额 ≥ 门槛，按折扣比例实付 | 充500打95折 → 实付475到账500 |
| 比例赠送 | 自定义金额按比例赠送（配置项，可选） | 充200送2% → 到账204 |

赠送金额入「赠送桶」，不可提现。

### 5.3 提现规则

- 手续费：后台配置（固定金额或比例）
- 最低提现额：后台配置
- 最高提现额：后台配置
- 每日限额：后台配置（当日累计提现上限）
- 提现只可提本金桶余额

### 5.4 冻结规则

- 冻结由**系统后台风控触发**（非用户端操作）
- 冻结期间：禁止充值、提现
- 冻结原因由后台下发，用户端只读展示

## 6. 后台配置联动

| 用户端元素 | 数据来源（后台模块） |
|-----------|---------------------|
| 充值预选档位 | 后台「充值方案」预选金额配置 |
| 充值活动 | 后台「充值方案」活动配置（满赠/折扣） |
| 提现规则（手续费/限额/审核方式） | 后台「钱包设置」 |
| 钱包开关/名称 | 后台「钱包设置」 |

> 注：后台「商户签约」决定充值收款方，属内部配置，用户端不展示。

---

## 7. 状态流转

```
充值单：待支付 → 已到账 / 入账失败
提现单：待审核 → 处理中 → 已到账 / 已拒绝（含拒绝原因）
钱包：  正常 ↔ 冻结（后台风控触发）
```

---

## 8. 特殊说明

> **原型演示元素**：钱包首页右上角「冻结演示」按钮仅用于原型演示（模拟冻结状态、验证冻结交互），**实际产品中不存在**。真实产品的钱包冻结由系统后台风控触发，用户端无此操作入口。

## 9. 交互说明

- 弹窗关闭四路：按钮 / ✕ / 遮罩点击 / Esc
- 金额输入：等宽数字（tnum）、输入即算（手续费/到账联动）
- 操作反馈：Toast + 弹窗 + 余额刷新
- 页面切换：首页 ↔ 充值 / 提现 / 明细，二级页面左上角返回键回首页
- 冻结状态：按钮置灰、操作拦截、提示条展示原因
